myKyar update — AI အမြန်နှုန်းနှင့် Online Room ပြင်ဆင်ချက်

ပြင်ဆင်ထားသည်
1. AI အဆင့် ၄ ဆင့်၏ စဉ်းစားချိန်ကို လျှော့ထားသည်။
   - Easy: 35 ms / depth 3
   - Medium: 90 ms / depth 5
   - Difficult: 180 ms / depth 8
   - Advanced: 350 ms / depth 12
   စက်နှင့် browser အခြေအနေအလိုက် အမှန်တကယ်ကြာချိန် ကွာနိုင်သည်။ Advanced သည် အမြန်ဆုံးမဟုတ်ဘဲ အဆင့်များထဲတွင် ပိုမိုစဉ်းစားသည်။
2. AI hint စာသားကို အဆင့်လိုက် အမြန်နှုန်းနှင့် ကိုက်ညီအောင် ပြင်ထားသည်။
3. Online Room တွင် ချိတ်ဆက်ထားသောသူငယ်ချင်း ပြတ်သွားပါက Host သည် နောက်တစ်ကြိမ် connection ကို လက်ခံနိုင်အောင် ပြင်ထားသည်။
4. Version မကိုက်သော သို့မဟုတ် မမှန်ကန်သော network message တစ်ခုကြောင့် Host ၏ netReady ပိတ်သွားပြီး ဆက်မကစားနိုင်တော့သည့် အမှားကို ပြင်ထားသည်။ မသိသော message ကို လျစ်လျူရှုမည်။
5. Network protocol စမ်းသပ်မှုတွင် လိုအပ်နေသော mock DOM methods များ ထည့်ထားသည်။

စမ်းသပ်မှု
- JavaScript syntax စစ်ဆေးမှု: အောင်မြင်
- Engine tests: အောင်မြင်
- Network protocol mock tests: အောင်မြင် (Room join, နှစ်ဖက်အလှည့်, state sync, invalid move rejection, rematch, အရောင်ပြောင်းခြင်း)
- AI tactics test: မူလ archive ထဲက စမ်းသပ်မှုမှာ Easy အပါအဝင် အဆင့်တိုင်းက tactical trap တစ်ခုကို ရှောင်ရမည်ဟု မျှော်လင့်ထားပြီး မူလဖိုင်အတိုင်း စမ်းသပ်ရာတွင်လည်း မအောင်မြင်ခဲ့သည်။ AI အဆင့်/အမြန်နှုန်းပြင်ဆင်မှုနှင့် သီးခြား engine tactics ပြဿနာဖြစ်သည်။
- Playwright UI test: Playwright dependency မပါဝင်သဖြင့် မစမ်းနိုင်ခဲ့ပါ။
- အမှန်တကယ် အင်တာနက်ပေါ်တွင် မတူညီသော network/browser နှစ်ခုဖြင့် Live WebRTC စမ်းသပ်ခြင်းနှင့် Firebase deploy ကို ဤနေရာမှ မလုပ်နိုင်ပါ။ Mock network test အောင်မြင်ခြင်းသည် public internet ပေါ်တွင် connection အမြဲအောင်မြင်မည်ဟု အာမမခံပါ။

တင်သွင်းနည်း
1. မူလ project ကို backup လုပ်ပါ။
2. ZIP ထဲက myKyar/public/ ဖိုင်များကို မိမိ project ၏ public/ ထဲသို့ ကူးထည့်ပါ။ public folder ကို အစားထိုးဖျက်မပစ်ပါနှင့်။
3. firebase.json ကို project root တွင် အစားထိုးပါ။ မိမိ .firebaserc နှင့် ကိုယ်ပိုင် config.js / network-config.js setting များရှိပါက backup မှ ပြန်ထည့်ပါ။
4. Project root Terminal မှ firebase deploy --only hosting --project kyar-mm ကို run ပါ။
5. နှစ်ဦးစလုံး browser ကို hard refresh (Mac: Cmd+Shift+R) လုပ်ပြီး Room အသစ်ဖွင့်ကာ code ကို Join လုပ်သူထံ ပို့ပါ။

မှတ်ချက်: PeerJS/WebRTC ချိတ်ဆက်မှုသည် browser permissions, firewall, NAT နှင့် TURN server လိုအပ်မှုတို့အပေါ် မူတည်နိုင်သည်။ မတူညီသော network နှစ်ခုဖြင့် စမ်းသပ်ပြီးမှ production-ready ဟု အတည်ပြုသင့်သည်။
